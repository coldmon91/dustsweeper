# dustsweeper 휴지통 이동 설계

이 문서는 2026-11-17에 승인된 휴지통 이동 설계다.
탐색기 화면은 `docs/specs/2026-11-17-browse-tui-design.md`를 따른다.
그 문서의 휴지통 금지와 `d` 키 무시는 이 문서가 대체한다.

이동은 선택한 항목을 사용자 휴지통으로 옮기는 것이다.
영구 삭제는 하지 않는다.
휴지통을 비우기 전에는 디스크 용량이 줄지 않는다.
파일 내용은 읽지 않는다.

## 하지 않는 일

- `rm`, `unlink`, 영구 삭제, 이름 변경, 끌어다 놓기
- `delete`와 `rm` 하위 명령. 둘 다 계속 종료 코드 2다.
- `나머지` 줄, 항목이 없는 목록, 지금 보고 있는 디렉터리 자신의 이동
- 확인 없이 이동
- 이동 후 `dust`를 다시 실행
- 새 패키지
- 휴지통 명령의 표준출력과 표준에러를 화면에 그대로 그리기

## 명령

이동 명령은 이 목록 그대로다.

`/usr/bin/trash -s <absolute-path>`

셸을 쓰지 않는다.
`--`를 붙이지 않는다.
`-v`를 붙이지 않는다.
경로는 하나이고 `/`로 시작한다.
그 외의 경로는 명령을 실행하지 않는다.

종료 코드 0이면 성공이다.
명령이 없으면 `trash not found`다.
종료 코드가 0이 아니거나 경로가 절대 경로가 아니면 `trash failed`다.
이 실패로 탐색기를 종료하지 않는다.
표준출력과 표준에러는 잡고 버린다.

## 키와 상태

상태에 `pending_path`와 `notice`가 추가된다.
`pending_path`가 없으면 확인 중이 아니다.
`notice`는 실패 안내이거나 없다.

상태 줄의 우선순위는 이 순서다.

1. `pending_path`가 있으면 `휴지통으로 옮길까요? {보이는 이름}  y`
2. `notice`가 있으면 그 문장
3. 그 외에는 선택한 행의 크기와 비율

보이는 이름은 목록에 그린 이름이다.
디렉터리면 끝의 `/`를 포함한다.
확인 문장과 안내 문장에는 끝의 개행을 붙이지 않는다.

`d`는 선택된 항목이 `entry`일 때만 그 경로를 `pending_path`로 둔다.
`나머지`이거나 항목이 없으면 상태를 바꾸지 않는다.
확인 중 `y`는 `pending_path`가 아직 선택된 항목의 경로와 같을 때만 이동 요청이다.
다르면 이동 요청 없이 `pending_path`만 지운다.
확인 중 그 외의 키는 취소다.
취소는 `pending_path`만 지우고, 선택 위치와 스택과 종료를 바꾸지 않는다.
따라서 확인 중 `q`와 왼쪽 방향키는 종료하거나 상위로 이동하지 않는다.

안내 줄이 있을 때 다음 키는 안내를 지우고 그 키의 원래 동작도 한다.
확인 중에는 키가 취소로만 소비된다.

## 성공 후의 트리

이동 명령은 `tree.py`가 실행하지 않는다.
이동 요청은 키 결과의 `trash_path`다.
`tui.py`가 성공을 확인한 뒤에만 트리를 갱신한다.
현재 디렉터리의 그 자식만 빠진다.
스택에 있는 각 조상의 `size_bytes`에서 빠진 자식의 크기를 뺀다.
결과가 0보다 작으면 0이다.
자식의 경로는 그대로다.
선택 위치는 유지한 뒤, 보이는 줄 안으로 당긴다.
`pending_path`는 지운다.
`dust`는 다시 실행하지 않는다.

## 파일 책임

| 파일 | 책임 |
|---|---|
| `src/dustsweeper/trash.py` | `/usr/bin/trash -s` 실행과 실패 문장 |
| `src/dustsweeper/tree.py` | 확인 상태, 키 결과, 성공 후 자식 제거 |
| `src/dustsweeper/tui.py` | 확인 줄, 이동 호출, 성공 후에만 트리 갱신 |
| `tests/test_tree.py` | 확인, 취소, 크기 감소 |
| `tests/test_trash.py` | 가짜 실행기의 성공과 실패 |
| `README.md` | `d` 다음 `y`로 휴지통에 옮긴다는 문장 |

`trash.py`는 `curses`를 가져오지 않는다.
`tree.py`는 휴지통 명령을 실행하지 않는다.
소스와 README에 `os.remove`, `os.unlink`, `shutil.rmtree`, `send2trash`를 두지 않는다.

키 결과는 `state`, `quit`, `trash_path`다.
이동 요청이 없으면 `trash_path`는 없다.
`quit`이 참이면 종료 코드 0이다.

## 검증

테스트는 `/usr/bin/trash`를 실행하지 않는다.
가짜 실행기는 인자 목록을 받고 종료 코드를 돌려준다.
성공 인자 목록은 `["/usr/bin/trash", "-s", "/tmp/item"]`이다.
`--`가 있으면 실패다.
상대 경로는 실행기를 호출하지 않고 `trash failed`다.
명령이 없으면 `trash not found`다.
종료 코드가 0이 아니면 `trash failed`다.
실패 후의 스택은 호출 전과 같다.
크기 30인 자식을 빼면 부모 100은 70이 되고, 그 위 조상도 30이 줄어든다.
확인 중 왼쪽 방향키는 스택을 바꾸지 않는다.
